# 灰燼の誓い — 第1章「戦士と石門」

スマホ縦持ちを中心に設計した、**オリジナルの2D・章立てJRPG**の動作プロトタイプです。昔のコマンドRPGの遊び心地を目指しつつ、キャラクター・物語・ドット絵は独自制作です。

**起動ファイル：`index.html`（これだけで動作します）**

## 1. 実装済み（バージョン 0.1）

- 画面上部 約60％：ドット絵のフィールド・会話・戦闘画面
- 画面下部 約40％：十字キーと A / B / X / Y の4ボタン
- スマホのタッチ操作（十字キーの長押し移動対応）とPCキーボード操作
- 村の廃墟 → 街道 → 王都 → 旧石門（ダンジョン） → ボス撃破 → 第1章のエンディング
- NPCとの会話、マップ境界でのエリア移動、調べる宝箱、王都での回復
- ターン制のコマンド戦闘：攻撃／防御／特技（MP3）／道具（やくそう）
- 初戦で「攻撃→防御」、ダンジョンで「特技・道具」、ボスで「予兆に応じた防御」を段階的に紹介
- HP / MP / 回復アイテム、レベルアップ、勝利数、全滅後の再挑戦
- ブラウザ内 `localStorage` へのオートセーブと「つづきから」
- 通信・追加画像・外部ライブラリ・ビルド工程なし

### 操作方法

| 操作 | スマホ | PC |
|---|---|---|
| 歩く・コマンドを選ぶ | 十字キー | 矢印キー または WASD |
| 決定・会話・調べる | A | Enter / Space / Z |
| 戻る・会話を進める | B | Esc / C |
| 冒険メニュー | X | X / M |
| ステータス表示・戦闘のヒント | Y | Y / H |

- 人物や宝箱の**隣に立ち、A**で話す／調べる。
- 街道・王都・ダンジョンの境目は、開いている道に沿って画面端まで歩くと移動できます。
- 会話は画面上の会話枠をタップしても進められます。戦闘コマンドは直接タップも可能です。
- 保存内容は**同じブラウザ・同じ配信URL**に紐づきます。閲覧履歴の削除やブラウザ変更では引き継がれない場合があります。

## 2. すぐ試す

### ローカルで試す

`index.html` をChromeやSafariなどのブラウザで開いてください。サーバーなしでも動作します。

### GitHub Pagesで公開する

1. GitHubで新しいリポジトリを作ります。例：`ashen-oath`。
2. リポジトリの最上位階層に `index.html` をアップロードします。このREADMEも置いて構いません。
3. **Settings → Pages → Build and deployment → Deploy from a branch** を選びます。
4. Branchは `main`、Folderは `/(root)` を指定して保存します。
5. 公開後、表示される `https://ユーザー名.github.io/リポジトリ名/` にスマホからアクセスします。

GitHub Pagesの設定表示・反映時間は変更される場合があります。初回公開後はリポジトリのPages画面で公開URLを確認してください。

## 3. 第1章のストーリー進行と学習設計

| 順番 | 場所／イベント | 学ぶシステム | 次へ進む条件 |
|---|---|---|---|
| 1 | 焼け落ちたミルト村 | 歩く・人と話す・目的を見る | ミラと会話して東の道へ |
| 2 | 東の街道：灰のスライム | 攻撃→防御（初戦チュートリアル） | スライム撃破、街道を東へ |
| 3 | 王都アステル | NPC会話・HP/MP回復・メニュー | バルドに志願し北門へ |
| 4 | 旧石門：洞窟コウモリ／宝箱 | 特技・MP・道具・探索 | 魔物に勝ち、石門を奥へ |
| 5 | 石門の番兵 | 予兆と防御、HP/MP管理 | ボス撃破で章クリア |

### 物語の核

- 主人公レオン：故郷を襲われた若い戦士。復讐心から出発するが、「生き残った人々を守り抜く」意志へ変化する。
- ミラ：村の生存者。レオンに「生きて戻る」ことの重要性を伝える。
- バルド：討伐隊の隊長。復讐だけを動機に戦うことの危うさを見抜く。
- 石門の番兵：攻撃力だけでなく、自分の命を守る判断を試す存在。
- 全体の主題：**「敵を倒すこと」ではなく「守るために生き残ること」。**

## 4. 次に進める開発順序

### フェーズA — 今回：縦スライス（完了）

第1章の開始〜エンディングが単一HTMLで通る状態を先に作る。UIの縦画面・会話・マップ・戦闘を一体として検証する。

### フェーズB — 操作感・バランス調整（優先度：高）

1. スマホ実機でボタンの押しやすさ、誤タップ、文字の読みやすさを検証する。
2. 街道・ダンジョンの移動距離、戦闘ターン数、ボスの難度を調整する。
3. 目的地の案内、NPC／出口の視認性、会話送りの体感速度を改善する。
4. 効果音、画面遷移演出、ダメージ表現、HPバー、メッセージ速度の設定を追加する。

**完了基準：** 初見プレイヤーが操作説明なしでも15〜30分程度で第1章をクリアでき、詰まる箇所を説明できる。

### フェーズC — RPGシステム強化（優先度：中）

1. エンカウントをイベント固定から、確率遭遇／シンボル遭遇の選択式へ。
2. 武器・防具・装備画面、ドロップ品、店、通貨の導入。
3. 状態異常、攻撃力／守備力、属性、敵行動パターンなどの戦闘拡張。
4. 複数のセーブスロット、会話ログ、ゲーム内設定を整備する。
5. セーブデータのバージョン移行を実装する。

**完了基準：** 第2章以降に戦闘ルールとデータ形式を再利用できる。

### フェーズD — オムニバス構造（優先度：中）

1. `chapterId` / `chapterState` / `party` を導入し、章の切り替えを管理する。
2. 第2章以降に別主人公・異なる職業・独自チュートリアルを実装する。
3. 各章の伏線・人物関係・地理情報をシナリオ資料として独立管理する。
4. 複数章クリア後に仲間が合流する共通章の基盤を作る。
5. 章ごとに進捗保存し、クリア済み章を再訪できる仕組みを検討する。

**完了基準：** 第2章を追加しても第1章のマップ・バトルを壊さず運用できる。

### フェーズE — 長期的なファイル分割・公開

最初は単一HTMLを維持しますが、仕様が固まった段階で次のように分割するのが推奨です。

```text
index.html
src/
  game.js           # メインループ・状態遷移
  maps.js           # フィールド／移動／イベント
  battle.js         # ダメージ・AI・戦闘フロー
  ui.js             # メニュー・会話・コントローラー
  story/
    chapter1.js     # 第1章のイベント／台詞
    chapter2.js     # 第2章のイベント／台詞
  data/
    enemies.js      # 敵・能力値
    items.js        # アイテム・装備
  save.js           # セーブデータと移行処理
assets/             # 将来の独自ドット絵・音声素材
```

※フォルダ構成は**将来案**であり、現バージョンでは `index.html` 以外は不要です。分割後もGitHub Pagesで配信可能です。

## 5. 重要な現時点での制約

- 今回は**遊べるプロトタイプ**です。台詞・マップ規模・バランスは仮置きです。
- フィールドは固定マップ4枚で、キャラグラフィックはCanvasで手描き風に描画します。外部のドラクエ素材等は使用していません。
- 現状、NPC移動・ランダムエンカウント・装備・ショップ・仲間の加入は未実装です。
- セーブはブラウザ側に保持します。サーバー同期・アカウント機能はありません。
- スマホの縦画面を優先し、横画面は動作自体が可能でも最適化の対象外です。
- 難易度はチュートリアル用に低めです。今後の実機テストで調整します。

## 7. 開発上のルール

- このプロジェクトの**唯一の仕様源は、このチャット内の依頼と本ファイル**とします。ほかの会話で進めたゲーム設定は混在させません。
- 章を追加するときは、実装前に「章の主人公・テーマ・目的・学ぶシステム・前章との伏線」を1ページにまとめます。
- シナリオの成長線とチュートリアルを対応させ、説明文をただ並べるだけにしない方針です。
- 新規の章や機能を追加する際は、必ず第1章を最初から最後まで再テストします。
