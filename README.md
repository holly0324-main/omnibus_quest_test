# 灰燼の誓い — 第一章「戦士と石門」 v0.2

スマホ縦持ち用オリジナル2D JRPG。v0.1単一HTML版から **ES Modulesベース** のゲームへ再設計。
本プロジェクトの仕様と設定は、このチャット内だけで独立管理します。

## 起動

### GitHub Pages（推奨）
1. このフォルダの **index.html / style.css / src/** をリポジトリのルートへ配置。
2. GitHub の `Settings → Pages → Build and deployment` で `Deploy from a branch` と `main / (root)` を選択。
3. Pages URLをスマートフォンで開く。外部API、画像CDN、npm、ビルド処理はいずれも不要。

### PC ローカル
`index.html` を直接 `file://` で開くとブラウザの ES Modules セキュリティ制限で動作しない場合があります。

```bash
cd ashen-oath-v0.2
python3 -m http.server 8000
```

`http://localhost:8000/` へアクセス。通信はローカルPC内だけ（公開先ではHTTPS）。

## 操作

- 十字キー／PC矢印・WASD：**押しっぱなしで滑らかに移動**。斜め移動は速度を正規化。
- A／Enter・Space・Z：決定／会話／調べる
- B／Esc：戻る。戦闘の最上位画面では逃走（ボス以外）
- X：探索メニュー（道具・装備・強さ）
- Y：強さの画面を直接開く
- メニューは画面タップ、または十字キーとAでも操作可能。

## 第1章の遊び方

1. 廃村でミラと会話 → 東の出口から世界マップへ。
2. 世界マップの街道・草地を探索。シンボルに入れば村・王都へ移動。野外ではランダムエンカウント。
3. 道中の野営地で一度休憩できる。広い王都で鍛冶屋・薬師を訪ね、隊長バルドに志願。
4. 北門から旧石門へ。途中の宝箱には「鉄の剣」。
5. 最奥の「石門の番兵」を倒して章をクリア。

## 今回実装済み

| 分野 | 実装 |
|---|---|
| 描画 | Canvas 320×360、**固定30FPS**、カメラ追従、ピクセル描画 |
| 探索 | 連続座標移動、長押し・斜め移動、衝突判定、スクロールマップ |
| フィールド | 廃村 42×34、**世界地図 72×54**、王都 56×45、旧石門 46×42 |
| 行き来 | 村出口→世界、世界シンボル→村／王都、北門→ダンジョン、引き返し可能 |
| 敵 | 野外/ダンジョンのランダムエンカウント、ボス、逃走 |
| 戦闘 | コマンド式、斬撃演出、被弾点滅、ダメージ数字、振動表現、負傷差分、HP非表示 |
| 特技 | **階層メニュー**：強打／気合／崩し斬り（Lv2習得） |
| 装備 | 武器・鎧スロット、道具欄、店で購入、宝箱から取得、ステータスへ反映 |
| 成長 | 経験値、レベルアップ、攻防HP/MP成長、所持金 |
| フィールド休憩 | 道中の野営地で一度だけHP・MPを回復 |
| 保存 | localStorageに自動保存（マップ移動・メニュー操作・戦闘終了・探索中9秒おき） |

## ディレクトリ構造

```text
index.html      # 初期HTML／Canvas／コントローラーのみ
style.css       # スマホレイアウト・ボタン・UIの装飾
src/
  main.js       # アプリ初期化／30FPS固定更新ループ
  data.js       # マップ、NPC、アイテム、敵、特技、ゲーム定義
  world.js      # 連続移動、衝突、出入口、NPC、フィールドエンカウント
  battle.js     # 戦闘状態遷移、ダメージ処理、勝利／敗北
  renderer.js   # Canvasによるマップ／キャラ／戦闘演出
  ui.js         # 会話、コマンドメニュー、装備、買い物
  input.js      # 長押し・マルチタッチ・キーボード
  storage.js    # セーブデータv2の保存／読込
```

## アーキテクチャ上の注意

- HTMLはCanvasとボタンのみ。ゲームロジックはJavaScriptモジュールに分離済み。
- 描画と入力・ゲーム進行の責務を切り分けた状態駆動型。外部ライブラリ不使用。
- セーブキーは `ashen_oath_chapter1_v2`。v0.1とデータ構造が異なるため**旧セーブデータは自動引継ぎしない**。
- 30FPSは更新・描画上限の設計目標であり、端末性能やバックグラウンド状態で実際のFPSが落ちる場合がある。
- ドット絵は現段階ではCanvasで直接描画。`renderer.js`の絵描き部分を将来画像スプライトへ差し替え可能。
- JavaScript ES Modulesなので `file://` ではなく GitHub PagesまたはHTTPサーバーで配信。
